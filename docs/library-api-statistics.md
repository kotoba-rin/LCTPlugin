# WordPress 文库接口统计

`wordpress/lctp-library-stats.php` 是独立的 WordPress MU 插件。将它与现有 `lctp-library-sync.php` 放在站点 `wp-content/mu-plugins/` 下即可启用；无需更新 Obsidian 插件或重新发布文库快照。

管理员登录后在「插件 → 文库接口统计」查看；「工具 → 文库接口统计」保留原入口，安装 Matomo 时也会显示「Matomo Analytics → 文库接口统计」。三个入口读取同一组服务器端统计，不向 Matomo 访客流量中写入接口请求。

- 累计、今日、近 7 天与近 30 天调用次数，近 7／30 天均包含今天。
- 累计 HTTP 状态分布及所选日期的逐日总数、正常返回、304 缓存校验和失败次数，默认显示最近 30 天。
- 统计启用时间、最近调用时间及站点时区。
- 自选开始／结束日期（含首尾，最多 366 天），并提供今天、近 7 天、近 30 天快捷筛选。
- 所选日期内 00—23 时的调用分布图及逐小时明细，区分正常返回、304 和失败。

## 统计口径

外部客户端通过 HTTP GET 访问 WordPress REST 路由 `/lctp/v1/project` 时，在 WordPress 准备发送响应时计一次。接口地址遵循站点固定链接配置，路径大小写和末尾斜杠不影响匹配。`HEAD`、`OPTIONS`、方法覆盖为 GET 的 POST、WordPress 内部子请求和查看统计本身均不计入。计数采用对外响应的 HTTP 状态，包含 200、304 和 4xx／5xx。使用 WordPress 的 `_envelope` 参数时，记录外层响应状态。

接口调用次数不等于文库下载量、同步成功次数或独立使用人数。静态 `manifest.json`、ZIP、正文、附件以及独立的 QQbot 内部库 API 不经过这一统计。被代理缓存直接响应或在进入 WordPress 之前被拒绝的请求也不在统计范围内。现有版本接口要求缓存重新校验；部署后应验证连续 GET 和条件 GET 均会递增计数。

按 WordPress 站点时区划分自然日和小时，启用和最近调用时间以 UTC 存储、在后台转换为站点时间显示。统计从启用时开始，不回填缺少依据的历史数字。更改站点时区后，已记录日期和小时不重新划分。

1.1.0 之前的汇总只保存日期，没有小时。升级会保留这部分计数，不把旧次数分摊到虚构的小时；页面显示小时统计的启用时间及所选范围内仅有日期的旧调用数。因此升级当日的每小时总数可能少于每日总数。

## 存储与权限

数据库专表 `{站点表前缀}lctp_library_api_daily` 保留旧版按日期和状态的汇总。1.1.0 升级后仅向新表 `{站点表前缀}lctp_library_api_hourly` 写入，每个日期、小时和 HTTP 状态一条汇总。每次请求只执行一条原子自增，避免并发覆盖和双重计数。报表在一条 SQL 查询中读取累计、逐日和逐小时计数，并单列所选日期内只有日记录的旧调用。这样即使同时有新请求，各项合计仍然一致。不保存 IP、User-Agent、用户 ID、设备标识、查询参数或请求正文。统计写入失败不会改变文库接口的响应，存储故障会写入服务端错误日志。

后台页面和只读统计接口 `GET /wp-json/lctp/v1/project/stats` 均要求 `manage_options` 权限。统计接口返回 `Cache-Control: private, no-store`，不向未登录访问者公开数据。其 `enabled_at`、`hourly_enabled_at` 和 `last_called_at` 字段为 UTC，`daily[].date` 及 `hourly[].hour` 为站点日期／小时。可同时传入 `start=YYYY-MM-DD&end=YYYY-MM-DD` 查询日期范围；省略两者默认近 30 天，只提供一个、日期无效、结束晚于今天或超过 366 天均返回 400。`range` 表示所选日期合计，顶部 `summary` 仍为累计／今日／近 7／30 天。

统计插件通过 WordPress 的响应过滤器计数，不修改公开元数据、ETag 或原有缓存头。可单独移除此 MU 插件以停止统计；已有统计表和汇总数据会保留。

## 验证

以下统计测试使用 PHP 的 PDO_SQLite 扩展，在内存数据库执行报表查询。WordPress 站点继续使用自己的数据库。

```bash
php -l wordpress/lctp-library-stats.php
php tests/test_wordpress_library_sync.php
php tests/test_wordpress_library_stats.php
php tests/test_wordpress_library_stats_periods.php
```

此外应在隔离数据库表上验证原子自增，在正式站点验证 200／304 请求递增、HEAD／OPTIONS 不递增、统计接口的管理员权限和后台页面渲染。

2026-11-10 已在正式站点启用。隔离的真实 WordPress／MySQL 验证中，4 个并发进程共写入 100 次，按 200／304／503 分别得到 36／32／32 次，无漏计。正式站点由 0 次增加到 2 次（200 和 304 各一次验收请求）；HEAD、OPTIONS 和统计查询均不递增，未登录统计查询返回 401，原有元数据与 ETag 保持一致。两组 PHP 行为测试及后台页面渲染验证通过。

2026-11-11 已升级至 1.1.0，小时统计从北京时间 20:02:47 开始；原有 23 次日统计完整保留。隔离 MySQL 表中 10 次旧调用与 106 次新调用合并为 116 次，其中 100 次来自 4 个并发进程，无漏计。三组 PHP 行为测试通过，包含日期边界、非法参数和并发快照回归。正式站点 200／304 验收请求使总数从 23 增至 25、小时统计从 0 增至 2；HEAD／OPTIONS 和查看报表未递增。未登录读取返回 401，无效时间段返回 400。已通过 Chrome 检查「插件」「工具」「Matomo」三个入口、日期筛选控件和小时图表。

2026-11-21 在隔离的 WordPress 7.1.5 和 MariaDB 11.4.14 上验证了 1.1.1。40 个并发 GET 全数计入，升级前的 9 次日记录完整保留。内部预加载及覆盖为 GET 的 POST 均未增加计数。`_envelope` 包装的 503 按外层 200 计数，匿名读取统计的拒绝响应带有 `private, no-store`。查询式固定链接和后台逐小时明细也已验证。
